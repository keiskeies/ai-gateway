## 0. 定位

**产品**：本地优先的 AI API 网关，管理员用它配置上游平台、定义虚拟模型、分配 Key，并观察请求如何被路由。
**用户**：技术型管理员 / 独立开发者 / 小团队运维。
**页面的单一任务**：让管理员在 3 秒内知道“网关是否正常、哪里在出错、下一步去哪里处理”。

这不是一个通用 SaaS 后台，也不是一个营销首页。它是一个**运行中的信号控制台**。

---

## 1. 设计论点

### 1.1 一句话

**把“请求如何被路由”做成界面的主角，而不是藏在三个 CRUD 页面背后。**

### 1.2 核心隐喻：Signal Room / Patch Bay

Gateway 的世界由信号、线路、节点、衰减、故障组成。设计语言借用**机架、配线架、示波器**的秩序感，而不是“卡片 + 图表”的仪表盘模板。

- 主视觉是一张**路由主干（Signal Spine）**：`API Key → 虚拟模型 → 路由 → 后端`。
- 它同时是数据可视化、导航和状态入口；不是装饰性的流程图。
- 页面其余部分保持安静：深蓝灰面板、细线、等宽数字、克制的状态色。

### 1.3 设计风险（有意为之）

**把首页最显眼的位置留给一条会流动的路由主干，而不是 4 张 KPI 卡。**
这条主干承载实时流量、失败节点和点击下钻；如果去掉它，页面会退回成普通的监控大屏。我们承担这个风险，因为它直接表达产品最独特的能力。

### 1.4 不做什么

- 不做霓虹发光、彩色光晕、玻璃拟态堆叠。
- 不做“大数字 + 小标签 + 渐变强调”的通用 KPI 卡片墙。
- 不把每个区块都做成圆角卡片；用面板、分隔线、留白建立层级。
- 不在非序列内容上使用 01/02/03；只有首次配置向导是真正的步骤。
- 不让状态色参与数据系列配色；绿/琥珀/红只表达状态。
- 不为了动效而动效；整页只有一个持续动效：路由主干上的信号脉冲。

## 3. 字体

现有系统使用系统字体。为了让控制台有“仪表”而不是“模板后台”的性格，引入三字体系统；生产环境自托管，避免离线依赖。

| 角色 | 字体 | 用法 |
| --- | --- | --- |
| Display | **Archivo** 600/700 | 品牌字、页面标题、空态大标题；用量克制 |
| UI / Body | **IBM Plex Sans** 400/500/600 | 正文、表格、表单、导航 |
| Data / Mono | **IBM Plex Mono** 400/500 | KPI 数字、ID、时间、URL、Token、追踪、标签 |

为什么是这组：

- Archivo 的工业grotesque气质接近设备面板，但不像常见 AI 产品那样使用 Space Grotesk / Inter。
- IBM Plex Sans 为密集界面设计，中文回退到系统中文黑体，阅读稳定。
- IBM Plex Mono 让数字和路由信息有“测量值”的质感；等宽表格更易扫描。

### 3.1 字号阶梯

| 级别 | 桌面 | 用途 |
| --- | --- | --- |
| Display | 34/38 | 监控墙大标题 |
| H1 | 28/34 | 页面标题 |
| H2 | 18/24 | 区块标题 |
| H3 | 14/20 | 面板标题 |
| Body | 13/20 | 正文、表格 |
| Small | 12/18 | 辅助说明 |
| Caption | 10/14 | 等宽标签、时间戳、eyebrow |
| Readout | 30/34 | KPI 数字（等宽） |

- 中文正文不低于 12px；10px 只给等宽大写标签/时间戳。
- 数字统一 `font-variant-numeric: tabular-nums`。
- 标题字距 `-0.02em`；等宽标签字距 `0.10–0.16em`。
- 生产：`@fontsource/archivo`、`@fontsource/ibm-plex-sans`、`@fontsource/ibm-plex-mono`，或自托管 WOFF2 到 `frontend/public/fonts`。

## 5. 签名元素：Signal Spine

### 5.1 它是什么

一条从左到右的路由主干：

```
CLIENTS ──▶ VIRTUAL MODELS ──▶ ROUTES ──▶ BACKENDS
```

- 每个节点是一个小面板：标签、数量、状态点、简短说明。
- 节点之间的线是细的；线上有 1–3 个缓慢移动的信号点。
- 失败节点有琥珀/红色细环；选中节点用 `--signal` 边框。
- 节点可点击：Clients → Keys，Models → 模型列表，Backends → 平台/健康，整条主干 → Traffic。

### 5.2 为什么不是装饰

- 节点数量、流量、失败数都来自真实数据。
- 点击节点直接下钻到对应页面/筛选；它是导航。
- 主干下方有一行“当前瓶颈”标注，例如 `P95 1.82s · 魔搭 1 延迟最高`。
- 没有数据时，主干变成首次配置的 3 步向导（真实的序列，才用 01/02/03）。

### 5.3 在模型详情里：Patch Bay

模型详情把主干展开成一块配线板：

```
┌ route ──────────┐        ┌ backend 01 ─────────────┐
│ round-robin     │────────│ 魔搭 1 · Qwen3.8       │
│ 2 retries       │        │ weight 3 · p95 1.42s   │
│ max 4096        │        ├ backend 02 ─────────────┤
│                 │────────│ 魔搭 2 · Qwen3.8       │
│                 │        │ weight 2 · p95 1.88s   │
│                 │        ├ backend 03 ─ [degraded] ┤
│                 │╌╌╌╌╌╌╌│ 魔搭 3 · 429 · 2.40s    │
└─────────────────┘        └─────────────────────────┘
```

- 路由节点在左，后端卡在右，中间是一条垂直总线；每个后端用水平短线接到总线。
- 选中后端：连线变强调色，右侧 Inspector 显示权重/优先级/能力/reasoning。
- 失败后端：连线变红色虚线，卡片保留但降饱和；不隐藏，管理员需要看到它。
- 权重不是装饰：连线旁标 `w3`，或在卡片上显示权重胶囊。
- 可拖拽排序（生产实现）；键盘用上/下按钮。

### 5.4 动效

- 信号点沿主干缓慢移动（4–6 秒一圈），只在 Live 状态运行。
- 失败节点每 2 秒轻微呼吸一次，不闪烁。
- `prefers-reduced-motion` 下全部停止；Live 状态仍用静态点表示。
- 不做粒子、发光、彩虹渐变。

## 7. 组件语言

| 组件 | 规则 |
| --- | --- |
| `InstrumentReadout` | 一个面板内的 4 列；等宽大数字 + 单位 + delta + sparkline；无独立卡片阴影 |
| `SignalSpine` | 节点 + 连接线 + 信号点；节点可点；有文本摘要（无障碍） |
| `RouteNode` | 路由策略、重试、max tokens；不是一个普通卡片 |
| `BackendSocket` | 平台/模型、权重、状态、P95；选中/失败/空闲三态 |
| `TraceStep` | 尝试序号、后端、状态码、耗时；用于 Traffic Inspector |
| `AttentionItem` | 左侧 2px 状态条 + 标题 + 元信息 + 箭头；不做彩色整卡 |
| `StatusDot` | 6px 圆点 + 文本；状态不只靠颜色 |
| `DataTable` | 单一面板、sticky header、行 hover、选中左线、数字右对齐 |
| `FilterChip` | 32px 高、1px 边框；激活用信号底，不用实心亮色 |
| `EmptyState` | 图标 + 一句说明 + 一个主行动；需要时用 01/02/03 步骤 |
| `SecretField` | 等宽掩码 + 显示需确认；创建后只显示一次 |

## 8. 动效

| 场景 | 时长 | 规则 |
| --- | --- | --- |
| 信号点沿主干移动 | 4–6s 循环 | 仅 Live；reduced motion 停止 |
| 失败节点呼吸 | 2s 循环 | 低幅度；不闪烁 |
| 面板 hover | 150ms | 边框/底色变化；不位移 |
| 行选中 | 120ms | 左侧线 + 淡底 |
| 数字更新 | 300ms | count-up；reduced motion 直接跳值 |
| 图表重绘 | 300–500ms | 统一曲线；不弹跳 |
| 页面进入 | 180ms | 轻微 fade/translate 2px；不夸大 |

## 9. 文案

- 用运营语言，不用营销语言：`网关正常`、`3 项需要处理`、`最近失败`、`当前瓶颈`。
- 不用“欢迎回来”“开始你的 AI 之旅”等空话。
- 按钮用动词：`查看流量`、`添加平台`、`新建虚拟模型`、`打开试验台`、`重试`。
- 错误包含“发生了什么 + 下一步”：`统计加载失败。数据截至 14:58:04。` + `重试`。
- 空态是邀请：`还没有虚拟模型。先添加平台，再建一个虚拟模型。` + `添加平台`。
- 技术词保留英文：Token、TTFT、API Key、P95；首次出现可在 tooltip 解释。
- 中英混排时，数字和英文两侧留空格；时间用本地时区。

---

## 10. 无障碍

- 正文对比度 ≥ 4.5:1；10px 标签只用于非关键信息。
- 所有节点/行可键盘到达；`:focus-visible` 2px 信号色外框。
- 主干提供文本摘要：`3 个 Key → 4 个虚拟模型 → 12 个后端，1 个降级`。
- 状态同时有文字/图标；失败节点有 `aria-label`。
- `prefers-reduced-motion` 停止所有循环动画。
- 表格有 caption/aria-label；Inspector 打开时焦点进入，Esc 关闭后回到触发行。
- 颜色不单独表达含义；色盲用户可通过状态文字/形状区分。

### 11.1 与现有 token 的关系

现有 `main.css` 的 `--wall-bg`、`--panel-bg`、`--panel-bg-2`、`--accent` 等继续保留，新增变量作为语义别名：

```css
:root {
  --ink: var(--wall-bg);
  --hull: var(--panel-bg);
  --plate: var(--panel-bg-2);
  --signal: var(--accent);
  --text: var(--text-1);
  --text-2: var(--text-2);
  --text-3: var(--text-3);
}
```

这样监控墙和旧页面不受影响，新页面逐步迁移。

### 11.2 字体加载

- 生产环境不要依赖 Google Fonts；把 WOFF2 放进 `frontend/public/fonts`，用 `@font-face` 加载。
- 中文回退：`"IBM Plex Sans", "Noto Sans SC", "Microsoft YaHei", sans-serif`。
- 字体加载失败时布局不跳动：`font-display: swap` + 预设 `size-adjust`（可选）。

## 12. 自我批评与取舍

### 12.1 这是不是又一个深色仪表盘？

是深色，但**不是**“KPI 卡片 + 折线图 + 表格”的模板。路由主干和配线板是产品独有的结构，且承担导航与下钻；如果把它们拿掉，页面会失去意义。这是与通用监控大屏的区别。

### 12.2 风险

- **主干可能被误解为装饰流程图**：必须保证节点可点、数据真实、失败可见、移动端有文本替代。
- **配线板在小屏难以表达**：< 1100px 改为纵向列表 + 简化连线；不强行保留横向。
- **字体引入增加包体**：只加载 3 个 family 的必要字重；中文回退系统字体；用 `font-display: swap`。
- **动画可能分散注意力**：只保留信号点/失败呼吸；其他全部静态。
- **技术用户更喜欢密度**：主干之外保持紧凑表格；不要为了“呼吸感”牺牲信息量。

### 12.3 已删除的配件

- 页面背景的彩色光晕：删除，只保留极淡的径向底色。
- 每个面板的彩色顶条：删除，只用左侧 3px 信号条在面板标题上。
- 过多的 eyebrow：只保留页面级 `RUN / OVERVIEW` 这类真实层级标签。
- 数字卡的渐变强调：删除，数字靠等宽字体和字号建立层级。
